# DefectBatch

Журнал контроля, база смесей и пользователи. Интерфейс основан на оформлении
MixControl Version 1.4 (commit 375db0bd09c2772e7bee183ab2addcdfea97354a).

## Запуск

Нужны Windows, Node.js **24.x**, SQL Server Express и ODBC Driver 17 for SQL Server.
Подключение использует текущую учётную запись Windows: пароль в коде не хранится.
У этой учётной записи должны быть права на создание новой базы при первом запуске
и на чтение/изменение данных DefectBatch при последующих запусках.

В папке приложения:

    npm ci
    copy .env.example .env
    npm run users:init
    npm start

Открыть http://127.0.0.1:5173/.
Открывать dist/index.html напрямую больше не нужно: формы работают через API.
Команда node serve.cjs также запускает сервер, но без автоматического чтения .env.

## SQL Server на рабочем компьютере

В .env укажите установленный экземпляр и отдельную базу:

    HOST=127.0.0.1
    PORT=5173
    DB_SERVER=localhost\MIXCONTROL
    DB_NAME=DefectBatch
    DB_DRIVER=ODBC Driver 17 for SQL Server

Здесь проверен экземпляр HOME_PC\MIXCONTROL. На другом ПК имя может быть,
например, localhost\SQLEXPRESS. Создаётся только база DB_NAME; таблицы:
Mixtures, Records, Users и служебная AppState. SQL-скрипт — sql/001-schema.sql.
Базы других приложений не используются.

Для предварительного создания структуры: npm run db:init.
Проверка подключения: GET /api/health.

## Данные

Все три раздела читаются и сохраняются в SQL Server. При первом открытии пустой
базы данные прежнего прототипа автоматически переносятся из localStorage браузера.
Перенос выполняется одной транзакцией; исходная локальная копия сохраняется.
Повторный автоматический перенос после очистки базы запрещён служебной отметкой.
В новом браузере без старых данных приложение начинает с пустой базы.

Обновление данных других открытых вкладок выполняется каждые 5 секунд.
Если запись уже изменена другим клиентом, сервер просит обновить данные.
Используемую в журнале смесь нельзя удалить — её можно архивировать.

Вход по логину и паролю обязателен. Четыре начальных логина: keyuser, quality,
admin, employer. Роли KEYUSER, QUALITY, ADMIN, EMPLOYER сохранены отдельно;
пока все роли имеют одинаковый доступ, различия в правах будут настроены позже.

Команда npm run users:init создаёт эти аккаунты и разные случайные пароли.
Пароли сохраняются в .local/initial-credentials.txt. Этот файл исключён из Git
и ZIP. Повторный запуск не сбрасывает уже назначенные пароли.
На другом ПК команда создаст собственные начальные пароли.

В SQL хранятся хеши scrypt с отдельной солью для каждого пароля. Сессии
хранятся в таблице Sessions, в браузере — HttpOnly cookie, срок сессии 8 часов.
Выход завершает текущую сессию. Изменение собственного пароля или назначение
нового пароля в редакторе пользователя завершает все сессии этого пользователя.
Для своего пароля используйте настройки аккаунта; минимальная длина 10 символов.
Свою учётную запись нельзя удалить во время работы.

Сервер по умолчанию доступен только на этом компьютере.
Настройка общего доступа по сети — отдельный этап.

## Интерфейс

Каждый заполненный фильтр получает отдельный крестик справа. Он сбрасывает только
этот фильтр. Кнопка «Очистить всё» появляется при активном поиске или фильтрах.
Период очищается целиком своим крестиком. Поиск очищается во всех трёх разделах.

## Проверки

    npm test

Тест проверяет валидацию и API на реальном SQL Server, создавая отдельную
DefectBatch_Test_<случайный номер>. Проверяет перенос, CRUD, уникальность,
связи, конфликты версий, сохранность после переподключения, вход четырёх ролей,
недоступность API без входа, выход, смену пароля и завершение сессий, защиту
от запросов с другого сайта. По завершении удаляет только созданную тестовую базу.

ZIP содержит исходники и package-lock.json. node_modules, .env, .local и файлы SQL Server
в архив не входят. При переносе исходников на другой ПК база данных автоматически
не переносится: для существующих серверных данных используйте резервную копию SQL Server.

Документация драйвера: https://tediousjs.github.io/node-mssql/
