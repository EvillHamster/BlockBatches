# Установка на рабочем сервере Windows

Приложение запускается на Windows-ПК или Windows Server. Сервер должен быть
включён, а SQL Server — доступен Windows-пользователю, под которым работает Node.js.
GitHub хранит исходники: базы, рабочие записи, пароли и системные драйверы оттуда
не переносятся. На новой установке создаётся отдельная база.

## 1. Подготовить сервер

Установить Node.js **24.x x64**, Microsoft SQL Server Express и **ODBC Driver 17
for SQL Server x64**. SQL Express, если уже установлен, повторно устанавливать
не нужно. Git нужен для команд ниже; вместо него можно скачать ZIP репозитория.

Администратор SQL должен создать базу `DefectBatch` и дать Windows-пользователю
приложения доступ к ней с правами изменения структуры (например, `db_owner`
только этой базы). Также нужен доступ к `master` для проверки существования базы.
Другой вариант — разрешить приложению самому создать базу. В текущем коде
используется Windows Authentication; SQL-логин и SQL-пароль не вводятся в `.env`.

Проверить в PowerShell:

```powershell
node --version
Get-OdbcDriver | Where-Object Name -Like '*ODBC Driver 17 for SQL Server*'
```

Версия Node.js должна начинаться с `v24`.

## 2. Скачать приложение

```powershell
New-Item -ItemType Directory -Path C:\Apps -Force
Set-Location C:\Apps
git clone https://github.com/EvillHamster/BlockBatches.git DefectBatch
Set-Location C:\Apps\DefectBatch
npm ci
Copy-Item .env.example .env
notepad .env
```

Если скачали ZIP: распаковать так, чтобы `package.json` оказался непосредственно
в `C:\Apps\DefectBatch`, открыть эту папку в PowerShell, выполнить `npm ci`,
скопировать `.env.example` в `.env`. Не копировать `node_modules` с другого ПК.

## 3. Указать свой SQL Express

Пример `.env`:

```dotenv
HOST=127.0.0.1
PORT=5173
DB_SERVER=localhost\SQLEXPRESS
DB_NAME=DefectBatch
DB_DRIVER=ODBC Driver 17 for SQL Server
COOKIE_SECURE=false
```

В `DB_SERVER` указать **реальное имя установленного экземпляра**. Если в SSMS
подключаетесь к `ИМЯ-ПК\SQLEXPRESS`, указать именно его. `MIXCONTROL` из исходного
образца — имя экземпляра на компьютере разработки, оно не обязательно совпадает
с рабочим сервером.

## 4. Первый запуск и создание keyuser

```powershell
npm run db:init
npm start
```

Открыть **на самом сервере** `http://127.0.0.1:5173/`. На новой базе появится
«Регистрация keyuser»: ввести имя, придумать логин и пароль, подтвердить пароль.
Пароль — 4–128 символов. После создания приложение выполнит вход. Остальных
сотрудников добавить в разделе «Пользователи».

Первый успешно зарегистрировавшийся получает роль keyuser. Регистрация после
этого закрывается, в том числе после перезапуска. Поэтому сначала создайте
свой аккаунт локально и только затем открывайте доступ другим компьютерам.
Если база уже содержит пользователей, появится обычный вход: обновление не
сбрасывает учётные записи и пароли.

Проверка сервера:

```powershell
Invoke-RestMethod http://127.0.0.1:5173/api/health
```

В ответе должно быть `ok: True`. Проверить создание записи и её сохранение
после остановки и повторного запуска приложения. Для пробного запуска окно
`npm start` оставить открытым.

## 5. Доступ коллегам

Для проверки в доверенной локальной сети остановить приложение, заменить
в `.env` `HOST=127.0.0.1` на `HOST=0.0.0.0` и снова выполнить `npm start`.
Администратору Windows разрешить входящий TCP-порт 5173 только для нужной сети.
На компьютерах коллег открывать `http://IP-РАБОЧЕГО-СЕРВЕРА:5173/`.
Адрес `127.0.0.1` на компьютере коллеги ведёт на его собственный компьютер.

Для постоянного рабочего размещения настроить HTTPS через IIS и автозапуск
Node.js. В [README](../README.md#5-автозапуск-после-перезагрузки-windows) приведены
настройки Планировщика заданий, а в следующем разделе — IIS/HTTPS. Задача должна
работать под Windows-пользователем, которому предоставлен доступ к SQL.
Для IIS оставить Node.js на `127.0.0.1:5173`, использовать `COOKIE_SECURE=true`.
Не запускать два экземпляра приложения одновременно.

## 6. Обновления и данные

Перед обновлением сделать резервную копию базы через SQL Server. Затем остановить
Node.js или его задачу, выполнить в каталоге приложения:

```powershell
git pull --ff-only
npm ci
npm start
```

Если настроен Планировщик, вместо последней команды запустить его задачу.
Миграции применятся автоматически; повторная регистрация keyuser не появится.
Рабочий `.env` не перезаписывать. `npm run users:init` для обычной установки не
нужен и при обновлениях не запускается.

Для переноса существующей рабочей базы на другой сервер использовать резервную
копию и восстановление SQL Server. Excel переносит журнал/смеси, но не аккаунты
и пароли. При импорте журнала источники связей должны присутствовать в файле
либо в целевой базе; лимит файла — 5 МБ и 5 000 строк.
